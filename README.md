# Sound Editor

Browser-based audio editor built with React 19 + Vite. Single-page application for loading, editing, and exporting audio files (WAV / MP3).

## Quick start

```bash
npm install
npm run dev          # dev server with hot reload (http://localhost:5173)
npm run build        # compile app/ → index.html + assets/ at the repo root (the published site)
npm test             # Playwright end-to-end tests against the built site
npm run test:build   # build, then test
npm run format       # Prettier over app/src and tests
```

Node 20+ is required. Playwright uses the Chromium that `npx playwright install chromium` provides (preinstalled in Claude Code cloud sessions).

```
  index.html                 Vite entry HTML (base styles, #root)
  favicon.svg                bundled as a hashed asset

vite.config.js               build config (root = app/, outDir = repo root, version banner)
playwright.config.js         serves the built site with `vite preview`
```

### Deployment

GitHub Pages publishes the repository root, so the **built** `index.html` and `assets/` are committed alongside the source. Always run `npm run build` before committing a source change; the build deletes the previous `assets/` so stale hashed bundles never accumulate. Building into the parent of Vite's `root` is intentional; only `index.html` and `assets/` are written (the config silences Vite's generic warning about it).

### Version banner

The top-right corner shows `<branch> | <YYYY-MM-DD HH:MM JST>`. `vite.config.js` fills it in at build time from `git rev-parse --abbrev-ref HEAD` and the current Tokyo time (`__APP_BRANCH__` / `__APP_BUILD_TIME__`, read by `app/src/version.js`). Set `APP_BRANCH` / `APP_BUILD_TIME` in the environment to override (e.g. for a reproducible build).

### Geometric placeholder (`placeholder/`)

When no audio files are loaded, the waveform area shows an animated overlay of Islamic geometric motifs (8-pointed stars, hexagonal rosettes, diamond lattices) that fade in and out at random intervals. It is deliberately independent of React:

- **Container detection:** the largest `<canvas>` inside `#root`; its parent hosts `#waveform-placeholder`.
- **Visibility:** a `MutationObserver` on `#root` checks for the `"Ctrl+O or drag & drop"` empty-state text that `FilesPanel` renders. Loading hides the overlay instantly; closing all files fades it back in.
- **Resize:** a `ResizeObserver` rebuilds the 72 px tile grid. `pointer-events: none` keeps drag & drop working.

If you change the empty-state text in `FilesPanel`, update `findEmptyStateNode()` too.

### FileData

```
{
  id: "...",                   // crypto.randomUUID()
  audioBuffer: AudioBuffer,    // Decoded audio (Web Audio API)
  fileName: "example.wav",
  selectionStart: null,        // Seconds (number or null)
  selectionEnd: null,          // Seconds (number or null)
  zoom: 1,                     // 1 = whole file fits the view
  scrollX: 0,                  // px
  currentTime: 0,              // playhead, seconds
  noiseProfile: null,          // Float32Array or null
  history: [],                 // AudioBuffer snapshots (undo)
  historyIndex: 0,
  modified: false
}
```

WAV files get `audioBuffer._originalBitDepth` (8/16/24/32), `_originalSampleRate`, `_originalChannels` and `_originalFileSize` at load time. Edits create new `AudioBuffer`s, so `copyOriginalMeta(src, dst)` carries these fields forward in `setAudioBuffer`, `pushHistory` and `cloneAudioBuffer` — otherwise the first edit would silently drop them and the default export would fall back to the AudioContext rate / 24-bit.

`setSelection` and `setCurrentTime` clamp their inputs to `[0, duration]` of the active file.

## Audio processing pipeline

### File loading (`audio/decode.js` → `decodeAudioFile`)

Decoding fallback chain:
1. `decodeAudioData()` — native Web Audio API
2. Strip ID3 tags, retry `decodeAudioData()`
3. Try alternate sample rates (44100, 48000, 22050, 16000)
4. HTML media element fallback
5. mpg123 WASM decoder (MP3); the true sample rate is re-read from the MPEG frame header

`actions/fileActions.js` then reads WAV format metadata with `readWavFormat` and adds the file to the store.

### Export (`export/`)

| Format | Function | Details |
|--------|----------|---------|
| WAV | `encodeWav(audioBuffer, bitDepth)` | RIFF/WAVE header + PCM. 8-bit = unsigned PCM, 16/24-bit = signed PCM, 32-bit = IEEE float. Unknown depths fall back to 16. Throws a readable error past the 4 GB RIFF limit. |
| MP3 | `encodeMp3(audioBuffer, kbps, opts)` | lamejs, CBR only. `opts = { mode, lowpass, quality }` — MPEG mode (0=stereo, 1=joint, 3=mono), lowpass Hz, quality 0-9. `async`: yields to the event loop every ~30 ms and reports progress (see below), so callers must `await` it. |

Export flow (`exportWithCurrentSettings` → `exportActiveFile(config)`):
1. Resolve the config (`exportConfig ?? defaultExportConfig(buffer, fileName)`) and normalize it with `normalizeExportConfig` — the same helper the settings modal and the size estimators use: `bitDepth` → 8/16/24/32; for MP3, `sampleRate` → nearest legal MPEG rate (8000/11025/12000/16000/22050/24000/32000/44100/48000) and `bitrate` → the range that MPEG version allows (8-160 kbps below 32 kHz, 32-320 kbps above).
2. Resample if needed (`resample`, `OfflineAudioContext` + optional lowpass by SRC quality).
3. Channels: `toMono`, or `toStereo` (WAV mono → stereo, or > 2 channels → first two). A mono source exported as MP3 "stereo" stays mono-mode.
4. Encode (`encodeWav` / `await encodeMp3`).
5. Download (`downloadBlob`; the blob URL is revoked after 60 s so large downloads can start).
6. Log the parameters actually written.

**History of the "Export failed" bug:** an 8-bit source WAV made the default config `bitDepth: 8`, and the settings modal had no 8-bit option, so the select *displayed* "16 bit" while the config kept 8. The WAV writer then fell through to the 32-bit float branch with a 1-byte stride and wrote past the end of the `DataView` (`Offset is outside the bounds of the DataView`). Fixed by implementing 8-bit PCM and normalizing the config everywhere.

#### Processing overlay progress

`ProcessingModal` shows the store's `processing` message after a 500 ms debounce, so quick operations don't flash. The debounce effect depends on **whether a message is present** (`[!!message]`), not on its text — otherwise live percentages would keep resetting the timer. `applyNoiseReduction` and `encodeMp3` update the text every ~30 ms (`Label... ` + 20-segment `█`/`░` bar + ` NN%`) and `await new Promise(r => setTimeout(r))` to yield. Follow this pattern for any other long synchronous loop.

#### MP3 encoding options (`vendor/lamejs.js`)

The vendored lamejs `Mp3Encoder(channels, sampleRate, kbps, options)` is patched to apply a 4th `options` argument before `lame_init_params()`:

| Option | Type | Default | Notes |
|---|---|---|---|
| `mode` | `0`/`1`/`2`/`3` | `STEREO(0)` | MPEG channel mode. `1` = Joint Stereo (MS encoding), `3` = Mono |
| `lowpass` | Hz | unset (LAME auto) | If `>0`, sets `lowpassfreq` — improves perceived quality at a fixed bitrate |
| `quality` | `0`–`9` | `3` | LAME algorithm quality. The pipeline passes `2` |

It also pins `out_samplerate` to the input rate when that is a legal MPEG rate; otherwise LAME's `optimum_samplefreq()` silently drops 44.1/48 kHz to 32 kHz whenever lowpass ≤ 15.25 kHz. This build's `assert` is a no-op, so a failing `lame_init_params()` does not throw — keep feeding it legal rates.

VBR is **not** available: the port references `VBRNewIterationLoop` / `VBROldIterationLoop` / `ABRIterationLoop`, which were never defined, so any non-CBR mode throws `ReferenceError` inside `lame_init_params`. `bWriteVbrTag` likewise stays disabled. To add VBR, swap the encoder (e.g. a WASM libmp3lame or `@breezystack/lamejs`).

#### Presets

| Preset | bitrate | channels | sampleRate | mp3Mode | lowpass | format |
|---|---|---|---|---|---|---|
| `music_high` | 192 kbps | stereo | unchanged (44.1 kHz if currently < 32 kHz) | joint | 20 kHz | mp3 |
| `music_small` | 128 kbps | stereo | unchanged (44.1 kHz if currently < 32 kHz) | joint | 16 kHz | mp3 |
| `voice` | 64 kbps | mono | 22050 Hz | joint | 15 kHz | mp3 |
| `custom` | — | — | — | — | — | — |

Editing any individual field switches `preset` to `custom`. The modal lists only legal MPEG rates for MP3, adds a non-standard source rate to the WAV list (so the select never shows a different value than the one used), offers 8/16/24/32-bit WAV, and warns when a rate below 32 kHz caps the bitrate at 160 kbps. **Save** stores the normalized config.

#### Size estimators

Both the settings modal and the FilesPanel "Preview" row use `export/exportConfig.js`:

- `estimateOutputBytes(config, duration)` — on the normalized config. WAV: `duration × sampleRate × channels × bitDepth/8 + 44`; MP3: `duration × bitrate × 1000 / 8` (exact for CBR).
- `estimateSourceBytes(audioBuffer, duration)` — source as 16-bit WAV, for the compression ratio.

Joint Stereo and Lowpass change quality, not size.

### Effects

| Effect | Implementation |
|--------|---------------|
| **Gain** | Slider -20 to +20 dB (selection required) with live preview via `previewGain`; applied on release (`applyGain`, linear factor clamped to 0–10, i.e. the full ±20 dB) |
| **Fade In / Out** | Linear ramp over the given duration from the selection start / to the selection end |
| **Noise Reduction** | Power-domain Wiener-style spectral subtraction with oversubtraction, spectral floor, and time/frequency gain smoothing (below) |

#### Noise reduction algorithm (`audio/noiseReduction.js`)

1. **Capture** (`captureNoiseProfile(buffer, start, end)`) — select a noise-only region (≥ one FFT frame), click _Capture Noise Profile_.
2. **Apply** (`applyNoiseReduction(buffer, profile, strength, start, end)`) — select the target region, click _Apply Noise Reduction_ (0–100 % strength).

| STFT parameter | Value | Notes |
|---|---|---|
| FFT size (`FFT_SIZE`) | `2048` | ~46 ms @ 44.1 kHz |
| Hop size (`HOP_SIZE`) | `512` | 75 % overlap |
| Window | Hann (`hannWindow`) | |
| FFT | iterative radix-2 Cooley–Tukey in place (`fft`); inverse via the conjugate trick (`ifft`) | |

**Capture**: for each frame, power spectrum `|X[k]|²`; accumulate per-bin `mean(P)` and `mean(P²)`; `std(P) = √(mean(P²) − mean(P)²)`. Result: `Float32Array` of length `2·(N/2+1)` laid out `[mean… | std…]`, stored in `FileData.noiseProfile`.

**Apply**: per frame and bin, with `N[k] = mean[k] + K·std[k]` and `s = strength / 100`:

```
g[k] = max(β, (P_x − α · N[k] · s) / P_x)        if P_x > 1e-20
g[k] = β                                          otherwise
```

clamped to `[β, 1]`, then smoothed across frequency (3-bin moving average) and time (`g ← γ·g_prev + (1−γ)·g`), multiplied onto the complex spectrum (phase preserved), rebuilt by Hermitian symmetry, inverse-FFT'd and overlap-added with the squared-window normalisation. Selection edges cross-fade with the original over one FFT length.

| Parameter | Default | Meaning |
|---|---|---|
| α | `2.0` | Oversubtraction factor |
| β | `0.05` | Spectral floor: minimum gain applied to the spectrum (≈ −26 dB) |
| γ | `0.6` | Temporal smoothing weight |
| K | `1.0` | Std multiplier in the noise floor |

Old magnitude-only profiles (length `N/2+1`) are squared into power with `std = 0`.

### Playback engine (`audio/playback.js`)

- `startPlayback(buffer, offset, duration, onTime, onEnded)` — start (offset clamped into the buffer)
- `stopPlayback()` — stop and disconnect all nodes
- `getLevels()` — peak levels for the meter

```
BufferSource → [ChannelSplitter → AnalyserL/R → ChannelMerger] → GainNode → Destination
```

### Selection editing (`selection/`, `components/waveform/`)

- Dragging clamps to `[0, duration]`; within `SNAP_PX` (8 px) of the clip start/end it snaps to exactly 0 / duration.
- Mouse-down within `GRIP_PX` (6 px) of a selection edge drags that edge (yellow grips, ↔ cursor).
- Movements under `DRAG_PX` (3 px) count as a click (seek, no selection).
- `SelectionBar` offers jump-to-start/end, In/Out time fields (`mm:ss.mmm`, `m:ss`, or plain seconds; Enter applies, Esc cancels, invalid input turns the border red), set-edge-to-clip-start/end/playhead and Clear.
- `revealTime(t)` scrolls a zoomed view so `t` is visible; `WaveformView` registers the handler.

## Notes for contributors / AI agents

- Edit `app/src/`, then `npm run build`, then commit **both** the source and the regenerated `index.html` / `assets/`.
- The version banner updates itself on every build; no manual edits.
- Keep the two size previews consistent by changing `export/exportConfig.js`, not the components.
- Any new export option or caller must go through `normalizeExportConfig`.
- Commit convention: conventional commits (`feat:`, `fix:`, `refactor:` …).
